# Build and runtime proof for Fire TV

Mercury is a Leanback Android application. The event's
[official FAQ](https://amazonappdev2026.devpost.com/details/faqs) says a Fire TV entry
may be demonstrated with **Android TV Emulator or the Fire TV/Vega simulator**; a
physical device is optional.

## Current evidence

| Check | Current state | Evidence |
|---|---|---|
| Kotlin unit tests and APK build | Passed for the previous master; the candidate is rebuilt in every PR | `.github/workflows/android.yml` |
| Compiled default endpoint | Public HTTPS Lambda URL; no ADB override is needed | `app/build.gradle.kts`, `CockpitUrlResolver.kt` |
| Normal Leanback launch | Automated in a fresh Android TV emulator | `.github/workflows/android-tv-emulator.yml` |
| D-pad golden path | Attribution → stage → single-use record-only confirm → fixed responder handoff | `scripts/android_tv_smoke.sh` |
| Runtime receipt | Pending the workflow-dispatch run for this candidate | `android_tv_runtime_receipt.json` will hold the content-addressed pointer |
| Physical Fire TV | Optional and not run | The FAQ does not require it |

The demo path is deliberately effect-free. Its deployment markers are labelled
recorded Mercury repository commits, not deployments of `checkout-api`; confirmation
returns `RECORDED_ONLY`, says no deployment pipeline was contacted, and the public
handoff endpoint accepts no responder-authored text. Operator-authenticated routes
remain separate for real deployment evidence and real handoffs.

## Reproduce the APK

Use JDK 17 and the Android SDK:

```bash
./gradlew :app:testDebugUnitTest
./gradlew :app:assembleDebug \
  -PmercuryCockpitUrl=https://leol25sezuvokpankox5cvjopm0gtvfa.lambda-url.eu-west-1.on.aws/
```

The same endpoint is the source default, so a normal launcher start uses the public
candidate without this Gradle property and without `COCKPIT_URL`:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell monkey -p io.github.upgradedev.mercury.wallboard \
  -c android.intent.category.LEANBACK_LAUNCHER 1
```

`COCKPIT_URL` remains a validated local-development override. It is not used by the
runtime proof.

## Automated Android TV proof

Dispatch **Android TV runtime proof** in GitHub Actions. It:

1. builds the APK with the intended HTTPS endpoint;
2. boots an Android TV image and installs that exact APK;
3. launches through `LEANBACK_LAUNCHER` with no URL extra;
4. sends the same D-pad key codes as a remote to stage, confirm and publish handoff;
5. rejects the run unless logcat contains the loaded endpoint and every native journey event;
6. uploads the APK, install/launch logs, full logcat, screenshot and JSON receipt together.

The receipt is generated by `scripts/write_android_tv_runtime_receipt.py`. It records
`build_sha`, `workflow_run_url`, `artifact_name`, `built_by_command`, `apk_path`,
`apk_sha256`, `adb_install_exit_code`, `normal_launcher`,
`endpoint_loaded_without_intent_override`, `endpoint_health_build_sha`, `runtime`, `remote_journey`, and
content hashes under `artifacts`. Readiness gate J4 checks those fields and the exact
journey event set.

The legacy physical-device route remains supported. `scripts/write_firetv_receipt.py`
writes `firetv_build_receipt.json` with `built_by_command`, `gradle_exit_code`,
`apk_path`, `apk_sha256`, and `device_run`; inside `device_run` it records
`device_model`, `fire_os_or_android_version`, `adb_install_exit_code`,
`launched_at_utc`, and `observed`.

## Remote contract

| Remote key | Effect |
|---|---|
| D-pad arrows | Move to the nearest enabled control |
| Select / centre | Activate the focused control |
| Back | Close a panel, then WebView history, then the app |

`MainActivity` maps remote key codes through `DpadBridge` into
`window.navigateDpad`. Desktop arrow keys use the same navigator, and both the Node
spatial-navigation spec and the Playwright golden-path test exercise that code.
